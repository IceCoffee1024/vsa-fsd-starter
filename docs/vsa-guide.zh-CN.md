# 垂直切片架构指南

> 本文是 [英文原文](vsa-guide.md) 的简体中文翻译。如有内容不一致，以英文原文为准。

## 组织单元

一个后端切片代表一个外部可观察的用例，例如 `CreateOrder` 或 `GetOrderDetails`。在技术栈允许的情况下，该用例的端点、输入验证、流程编排、数据访问、响应映射和针对性测试应放在一起。

## 模块边界

相关切片归属于同一个业务模块。模块拥有自己的领域规则和持久化状态。其他模块应通过明确的公共契约交互，而不是直接访问某个切片的内部类型或存储。

## 依赖规则

- 传输层代码可以调用同一切片中的用例处理器。
- 切片可以使用所属模块的领域模型和基础设施端口。
- 跨模块调用必须使用目标模块的公共 API 或集成消息。
- 共享技术工具必须与业务无关，并且只有在重复使用证明其价值后才应抽取。
- 通用 Controller、Service 和 Repository 层不能成为每个用例都必须经过的间接层。

## 最小模板标准

仅作为脚手架的模板只需说明预期边界，不应宣称具备可运行行为。可运行的参考模板必须至少包含一个端到端切片，用于演示验证、成功和失败响应、持久化边界的位置以及测试；为了演示真实边界，它可以按需发展为多个相互协作的切片或模块。示例能力必须保持所有权清晰且可替换，使采用方能够删除或替换某个用例或模块，而不必拆解无关的共享内部实现。

## 模块化单体指南

单体部署并不意味着共享内部实现。模块应具有明确的所有权、方向清晰的依赖以及可独立理解的用例。未来是否拆分服务应是部署决策，而不是当前建立清晰边界的前提。
